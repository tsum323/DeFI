- ✅ Схема БД (`backend/database/schema.py`): `pools, blocks, raw_logs, ev_*, sync_state,
  sync_gaps`; большие целые хранятся точно (TEXT)
- ✅ Синхронизация (`sync.py`): адаптивные окна, 64 подтверждения, проверка `blockHash`,
  непрерывное покрытие, `sync_gaps`, идемпотентность и возобновление; тесты на фейковой цепи
- ✅ Скрипты: `verify_pools`, `compare_fee_tiers`, `sync_pool`
- ✅ Подтверждение пулов (`verify_pools`, Alchemy): 0.30% создан в блоке 12376048, 0.05% — 12561607;
  адреса совпали с CREATE2, `factory_deploy_block 12369621` подтверждён
- ✅ Выбор основного fee tier (`compare_fee_tiers`, 30 дней): **wbtc_usdc_3000** — комиссии LP
  $302 866 против $2 635 у 0.05%; 5 702 swap (≥ 1000)
- 🟡 Загрузка истории wbtc_usdc_3000: блоки 12376048..26033547 (~97.9%) — 664 960 логов
  (533 999 Swap, 34 023 Mint, 50 076 Burn, 45 482 Collect); 2 открытых `sync_gaps` на 26033548+.
  Остановлено: исчерпан месячный лимит Alchemy (HTTP 429 «Monthly capacity limit exceeded»)
- ⏳ Калибровка газа по receipts NonfungiblePositionManager
- ⏳ Фикстуры реальных логов для теста декодера (`tests/fixtures/real_pool_logs.json`)

**Известные ограничения / блокер:**
- Основная стоимость загрузки — заголовки блоков (`eth_getBlockByNumber` на каждый блок с
  событиями, ~532 тыс. шт.), а не `eth_getLogs`. Оценка «≈0.5 $» была занижена; фактически ушло
  порядка 10 млн CU. Возможная оптимизация: `blockTimestamp` уже есть в ответе `eth_getLogs`,
  base fee можно брать пачками через `eth_feeHistory`.
- База `data/lab.sqlite` (~0.9 ГБ) живёт только в контейнере сессии и в git не попадает.
- Бесплатные PublicNode/dRPC не годятся для истории (не архив / окно ~100 блоков);
  `sync_pool` теперь требует архивный endpoint и не переключается на них.
